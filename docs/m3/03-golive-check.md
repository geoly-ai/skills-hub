# 上线自检：这张 PR 是干什么的

这份文件本身没有内容价值，它存在的理由是**一次真实的 PR 跑通**。

2026-09-01 配分支保护时，有三件事**只能靠一张真 PR 证明**，推理证明不了：

1. **required status checks 的真实名字。** GitHub 认的是字符串。写错的后果不是报错，
   是**所有 PR 永远 pending、一张都合不了**，而界面只说「等待 check」——
   很难看出是名字对不上。所以先让 workflow 真跑一次，从 API 里读回它记录的名字，
   再钉进 required checks。
2. **CODEOWNERS 是否真的生效。** 我早先把「团队不存在 = fail-closed」当成事实写进
   注释，被 Codex 纠正过 —— 那是推断不是证据。这张 PR 会显示它到底要不要 owner 审。
3. **`validate-pr.yml` 的分流判定。** 这张 PR 改的是 `docs/**`，
   按 §5 它既不是 submission（不只动 `submissions/**`）也不是 promotion
   （分支名不是 `promotion/hub-<N>`）—— 它应当被路径白名单**拒掉**。
   🔴 **如果它被放行了，说明路径白名单没起作用**，那比它被拒更值得查。

⚠️ 所以这张 PR 的「失败」很可能是**正确结果**。看的是失败的**理由**对不对。
