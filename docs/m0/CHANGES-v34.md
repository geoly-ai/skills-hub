# M0 v34 变更台账

Codex 第三十三轮：确认 v33 的三处收口**全部落实正确、没有过头**
（`nlink` 只查普通文件、守卫 0″ 的扫描范围与 `.tmp` 顺序、repair-child 的 `old_digest` 例外、
隔离路径改用 `repair-intent.generation`、五次校验的实质）。
剩两项实质修订，评审说完成后**可以通过 M0 并允许开始 M1**。

## ① 🔴 slot 表既不全，三元组也不足以判定

三处被驳，都成立：

- 正向 `swap + state=retired` 时，**`stage` 里仍是新树、`retired` 里是旧树，两个槽同时有效**。
  v33 只允许后者 —— 于是当 repair 的目标是**原事务 postimage** 时，
  **恰好把唯一需要的那个槽拒掉了**。
- 回滚中的 `swap`，`stage` 是否装着新树**取决于反向子状态**（`t_parked` / `restored` 时是），
  只看 `direction` / `op` / 原 `item.state` **区分不了**。
- 回滚 `install-new` 的 `restored` 行**过宽**：原项仍是 `planned` 时新树在 `stage`，**不在 `undo`**。

v34 改为**两步制**，并先定目标方向：

| 原 `direction` | repair 目标 | 期望摘要 |
|---|---|---|
| 缺席（正向） | 原事务 **postimage** | `new_digest`（`retire-only` 为「无树」） |
| `rollback` | 回滚 **preimage** | `old_digest`（`install-new` 为「无树」） |

然后按 `direction × op × state/反向子状态 × cleanup` 给出 **13 行候选槽表**
（含两处「两个槽同时候选」）。

🔴 **关键**：状态只用来**缩小候选范围**，最终一律以
「该候选槽的**实测摘要 == `target.digest`**」为准，**不能只信状态**。

## ② 身份等价类的结论说过头了

评审：核心公式 `路径 × 条目类型 × mode × 文件内容` **准确**，
但后半句「等价类之外的一切要么规范化、要么拒绝」**不成立** ——
时间戳、inode 号等**既没规范化也没拒绝，只是不参与等价类**。

v34 拆成三类写清：

| 属性 | 处置 |
|---|---|
| xattr / ACL | 🔴 **拒绝** |
| 目录 mode | 🔴 **强制规范化**为 `0755` |
| 普通文件 hardlink | 🔴 **拒绝**（`nlink != 1`） |
| **时间戳、inode、属主、生成计数…** | ⚠️ **既不规范化也不拒绝 —— 只是不参与等价类**，因此**摘要相同不代表这些属性相同** |

并把正文里残留的「精确匹配 / 身份」改为「**落入记录的等价类**」
（隔离恢复表的三行、`isolated` 前的重验、无法成像那一行）。

## ③ 五次校验编号

按建议编成 **①a**（槽摘要）/ **①b**（tx 指纹）/ **②**（复制后 tx 指纹）/
**③**（stage 结构）/ **④**（最终结构）—— v33 写「五次」却只给了四个编号。
