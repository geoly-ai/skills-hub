# 中文排版规则 T1–T12

doc-qa 引擎通用规则。判据写到能直接实现的程度；「例外区」对所有 T 规则生效，除非单条另写。

## 共同约定

**例外区**（不检查；脚注定义正文不在例外区，照常检查）：围栏代码块内；HTML 注释指令（include、table、data、widths 等）；图片与图的路径；链接的 URL 部分（链接文字照常检查）；`{#…}` 锚点块；`@fig:x` 类引用；类型包 glossary 章节表格里的「异写」列。

**纯文本**：去掉 `**`、链接只留文字、去掉锚点块后的文本。**字数**：纯文本去掉全部空白后的字符数（中文、拉丁字母、数字、标点都算 1）。

**报告粒度**：与 qa-engine.md §3 一致——同一规则同一行只报一条（保留定级最高的，注明另有 N 条）；单条规则超过 30 条时，非必改的超出部分折叠为一条汇总（「另有 N 处」，定级取被折叠问题中最高的），必改永不折叠。

**定级可调**：类型包 qa.severity_overrides 可以改定级；qa.engine_rules.exclude 可以关规则（售前类型包迁移期关闭 T 规则以保 golden，打开时差异登记为有意）。

**中文字符**：Unicode 区间 㐀–鿿 与 豈–﫿。下文用「汉」表示。

## 规则

| 编号 | 规则 | 自动判据 | 例外与说明 | 定级 |
|---|---|---|---|---|
| T1 | 中文与英文、数字之间留一个半角空格；中文与全角标点之间不留空格 | ① 缺空格：`汉[A-Za-z0-9]` 或 `[A-Za-z0-9]汉`；② 多余空格：`[，。；：！？、）」』]\s+` 后接任意字符，或 `\s+[，。；：！？、（「『]` | 单位与百分号归 T6；「第 3 章」要空格；`v1.0版本` 报缺空格；紧邻全角括号的英文不要求空格（「（API）」合规）；② 只查半角空白，全角空格（U+3000）视为有意版式留白不报（2026-09-15 校准） | 建议 |
| T2 | 中文语境用全角标点；同一句不混用半角与全角逗号、句号 | ① `汉[,;:!?]` 或 `[,;:!?]汉`；② `汉\.(\s|$)`；③ 同一句（以「。！？」切分）里同时出现「,」与「，」 | 数字内的「1,000」「3.5」「10:30」不算；英文整句（句内无汉字）不检查 | 建议 |
| T3 | 区间用短横「–」，不用波浪号 | `[0-9汉]\s*[~～〜]\s*[0-9汉]` | 飞书会把 ~ 当删除线标记吞掉；URL、代码块内不查 | 必改 |
| T4 | 引号全文统一；默认「」，品牌档案 quote_style 可选“” | ① 全文同时出现「」与“”两种；② 汉字旁用了半角 `"` 或 `'` 作引号 | ① 报在少数派的第一处；文中引用他人原文且原文用“”时，写进 qa-report 标撤回 | 建议 |
| T5 | 标题末尾不带标点；标题里不手写序号 | ① 标题纯文本以 `[。，；：！？、.,;:!?]` 结尾；② 以 `\d+(\.\d+)*[.、\s]`、`[一二三四五六七八九十]+[、.．]`、`第[一二三四五六七八九十\d]+[章节部分]`、`[（(]\d+[)）]`、`附录\s*[A-Z]` 开头 | 问句式标题（以「？」结尾）类型包可用 severity_overrides 降为提示；附录用 `.appendix` 标记，不手写「附录 A」；② 手写序号与自动编号一致（解析器渲染前会去掉）时全文汇总为一条「提示」，不一致或解析器不去掉的写法（中文序号、「第 N 章」）逐条报「建议」（2026-09-15 校准：9 个样张逐条报 121 处） | 建议 |
| T6 | 数字与单位：数字 + 半角空格 + 单位；百分号紧跟数字 | ① `\d(MB|GB|KB|TB|ms|s|px|pt|mm|cm|kg|W|Hz)\b` 缺空格；② `\d\s+%` 多余空格；③ 数字紧跟汉字量词（个、天、周、月、年、小时、分钟、次、条、页、项、人、台、套、倍）缺空格 | 专有写法不查：3D、4K、5G、H5、2x、v1.0、P0–P3、Top10；③ 与 T1 重叠时只报 T6 | 提示 |
| T7 | 同一列表内各项句末标点一致 | 同一列表同一层级的项，句末字符分三类：句号类（。．.）、分号类（；;）、无标点；出现两类及以上报一条 | 最后一项用句号、其余用分号的「分号列表」算一致 | 提示 |
| T8 | 术语一致：类型包 glossary 声明的术语不出现异写 | glossary 形如 `{"正写": ["异写1", "异写2"]}`；正文纯文本出现任一异写即报，消息给出正写 | 术语表章节整章不查（标题去掉手写序号与空白后整体等于受控别名「术语表」「术语与缩略语」「名词解释」「Glossary」之一，不按子串；或锚点 sec:glossary、骨架 id glossary；文档主标题等于这些别名时整篇不查；到下一个同级或更高级标题为止，含章内说明段落）；引号内原文不查；异写是正写的子串时按最长匹配，避免「测试用例」被「用例」误伤 | 建议 |
| T9 | 不用行内代码格式；代码只放代码块 | 例外区外出现反引号 | 与售前 L2（行内代码部分）等价；售前类型包迁移期只开 L2 | 建议 |
| T10 | 表格单元格不写整句长段 | 单元格纯文本字数 > tokens.json table.cell_chars_hint（80） | 数据块渲染出的表同样检查；「说明」「备注」列同样适用 | 提示 |
| T11 | 验收、预期结果类列不用空泛表述 | 列名匹配 `验收|预期|期望|判据|标准|结果`（类型包 banned_terms 的 columns 可改），单元格：① 含「等等、若干、相关、尽量、合理、适当、友好、及时、体验更好、性能高、显著」；② 整格只有「正常、成功、通过、符合预期、OK」 | 类型包 banned_terms 可追加词与列；① 的「相关」在「相关文档」这类名词短语里仍会报，写作者在 qa-report 标撤回并说明 | 建议 |
| T12 | 可读性：段落不超过 250 字，句子不超过 80 字 | ① 段落（p 块与高亮块）字数 > 250；② 以「。！？；」及英文句点加空格切分的句子字数 > 80 | 表格、代码块、标题不查；列表项按句子查 | 提示 |

## 实现提示

- 判据里的正则都在「纯文本」上执行，行号取解析结果里块的起始行（跨行段落报首行）。
- T1、T2、T6 三条在中英混排技术文档里量大：新类型包首轮样张先看数量，误报集中的判据在本文件补例外，不在类型包里各自打补丁。
- 本文件是规则的唯一定义处；qa-engine.md 只登记编号与来源。
