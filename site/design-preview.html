01

配色

中性色是「greenbar 台账纸」——极低饱和的绿偏（≈110°，S≈6%），不是纯灰、也不是暖米色。 主强调 --c-ink 是铁胆墨蓝，只负责「可点、当前、聚焦」；四个状态语义色与它完全分离， 彼此的色相跨度足够大，灰度打印下也能靠明度分开。

--c-verifiedpublished · 验证通过
--c-cautiondeprecated · Tier 1 · stale
--c-revokedyanked · Tier 2
--c-degradeddegraded · 被成员拖累
--c-neutralbadgeTier 0 · 无需注意
--c-bg页面底
--c-surface面板 / 行

04

capability 徽章

三档同时用两个通道编码：分段计量条（1/2/3 格，色盲与灰度下仍可读）+ 色相。 Tier 徽章一律 描边、透明底；状态标记一律 无边、着色底——形态不同， 所以 Tier 2 与 yanked 共用红色也不会被误读成同一件事。徽章后面永远直接跟真实 capability 名， 不让人去记「Tier 2 是什么意思」。

TIER 0none TIER 1network TIER 1network · external-tool TIER 2shell · credentials · writes-repo

非 geoly namespace 的 Tier 1/2 制品，安装时会强制展示 capability 并要求确认

--yes 可以跳过确认，但跳过这件事本身会写进安装账本。列表页把这句话放在徽章旁边， 而不是等到用户敲命令时才第一次看见。

05

信任链条与信任面板

详情页里信任面板紧贴标题、位于描述之上，占满正文宽度——不是右栏的一小格。 顶部的链条把「验过了」拆成四件独立的事，因为一个笼统的绿勾会掩盖到底验了哪一环。 🔴 链条表达的是验证轴，与 status 生命周期轴无关： 一个 published 的制品完全可能验签失败，一个 yanked 的制品签名照样有效。 验证失败用圈叉（）， 与 yanked 的裸叉刻意不同形。

07

yank / degraded / deprecated 警示条

这些是事实，不是错误：所以没有大图标、没有全宽实心红条、没有感叹号轰炸。 统一形态是「一根 3px 顶边 + 极淡底色 + 一句陈述句标题 + 可执行的下一步」。 三者顶边颜色不同、图标不同、措辞的主语不同（yank 是「它被撤了」，degraded 是「它被别人拖累了」）。

此版本已于 2026-08-19 被 yank：默认拒绝新装

reason：把部署密钥写进仓库内的临时文件，且未在结束时删除。 公告 GSA-2026-0007；替代版本 0.9.3。 显式 --allow-yanked 仍可安装，且这次跳过会写进安装账本。 已装的实例不会被强制卸载，check 会报告它。文件不会被删除。

此版本已于 2026-07-02 被 yank：默认拒绝新装

reason：作者请求下架，内容与 geoly/social-hub-cli 重复。 未声明替代版本，无安全公告——advisory 与 superseded_by 都是可选字段，缺席时只展示必填的 reason， 不要渲染一个点不开的「查看公告」按钮。

此 pack 被标记为 degraded：它锁定的一个必装成员已被 yank

pack 不可变，改不了它锁定的成员，所以 hub 不会自动 yank 它，而是在每张新快照里重算这个派生状态。 🔴 --allow-yanked 不放行 degraded——这是它与 yanked 最大的行为差别； latest 投影也会跳过它。

此版本已弃用，但仍可安装

维护者不再更新它。它仍参与 refcount，也仍出现在解析结果里；只是 latest 已指向 0.3.6。
