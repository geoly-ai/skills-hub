# dashboard —— skill 埋点数据平台（内部运营）

回答 `docs/telemetry/00-spec.md` §1 的三个问题，一个不多：

| 段 | 问题 | 拿来做什么决策 |
|---|---|---|
| 01 | 哪些 skill 真的在被用 | 谁进矩阵包、谁下架 |
| 02 | 装失败集中在哪 | 哪个客户端、哪个版本、什么原因 |
| 03 | 一次安装要多久 | 性能回归 |

**不是一个「看板」。** 页面按问题分段，段号就是问题号；每段开头写清这一段是拿来做什么
决策的。没有问题意识的图表不该存在于此。

## 🔴 数据边界：只能展示采集到的东西

采集面是规格 §2 的一张**穷举白名单**：

```
schema  eid  at  install_id  cli  os  arch  node
kind  result  artifact  version  client  scope  ms  reason
```

**表外的东西根本没有被采集** —— 没有用户名、没有路径、没有项目名、没有地理位置、
没有 referrer、没有命令行原文、没有异常栈。所以「加一个指标」在这里从来不是前端的事，
而是先要去改采集面并过评审。

这条边界在代码里由 `lib/whitelist.mjs` 兑现（正向 pick，不是黑名单扫描），
由 `test/whitelist-drift.test.mjs` 与 `src/telemetry.mjs` 对账（**加字段不同步就会红**）。

## 🔴🔴 平台自己会变成隐私问题 —— 这一条最要紧

`install_id` 是本机随机 UUID，与账号、机器名、用户名都没有映射，**单看它不指向人**。

但**一个能按 install_id 把时间线拉出来的界面，本身就是再识别工具**：排出来的是
「这台机器哪天装了什么、什么时候卸的、跑的是哪个 OS 和 CLI 版本」的完整轨迹。
规格 §6 的 **T-11** 说的正是它：源 IP + 稳定 `install_id` + 时间线 = 机器级追踪。
端点侧已经用「不记 IP、不记 UA」掐掉了 IP 那一半；**时间线那一半在这个平台手里。**

三条结构性措施（不是靠自觉）：

1. **界面上永远不出现具体 `install_id`，不提供按它筛选或下钻。**
   `lib/whitelist.mjs` 的 `stripIdentifiers()` 在归一化时**递归剥掉**任何
   `install_id` / `installIds` / `byInstallId` / `eid` 形态的键 ——
   服务端将来就算回了，也到不了页面。
   判据是**形态**（大小写、连字符、驼峰、`by` 前缀、复数都归一后再比），
   不是那两个确切的字面量。
2. **小样本抑制**，见下。
3. **抑制发生在服务端**：整个项目**没有一个 client component**
   （`test/no-client-secrets.test.mjs` 在断言这一条）。
   先把未抑制的聚合发给浏览器、再靠前端隐藏，等于把它公开了 —— 打开 devtools 就能看见。

> ⚠️ **想加下钻，先去改规格。** 这不是一个 UI 取舍，它是 T-11 的缓解措施本身。

### 小样本抑制：阈值与做法

**阈值 K = 5**（去重 `install_id` 数，不是事件数 —— 一台机器一天能制造几十条事件）。

| 规则 | 做法 |
|---|---|
| S1 全局标量 | 没有任何抑制时精确发布；总装机数 `< 5` 压成 `<5`；**缺失时显示「未提供」，不显示 0 也不显示 `<5`**。🔴 **有抑制时一律分桶**，见 S5 |
| S2 细分行 | 任何细分行必须 `installs >= 5` 才发布，否则并进一条只报**行数**的「未发布」行 |
| S3 **fail-closed** | `installs` 缺失 = 无法证明达标 = 按不达标处理 |
| S4 **互补抑制** | 🔴 恰好只抑制**一行**时，再把事件数最小的可见行也抑制掉 |
| S5 **不留减法锚点** | 🔴 表内**没有总计行**，被抑制的那一组也**不报事件合计**；并且**只要任何一张表有抑制，顶层 `total` / `installs` 就分桶发布**（区间，不是精确值） |
| S6 **不发布嵌套分布** | 🔴 `kinds` / `results` 这类交叉子组**连读都不读** |
| S7 **分位数另有门槛** | 🔴 `durations` 的行还要 `events >= 20` 才发布 |

**S3 的直接后果要说在明处**：服务端目前不返回 distinct installs，所以**现在所有细分表
都会整表走「无法核实门槛」，页面上只剩总数**。这是有意的 —— 反过来（缺 installs 就当达标）
等于把抑制器关掉，而它恰恰在数据最少、最容易被识别的那段时间里最需要开着。

**S4 为什么必须有**：只抑制一行时，把它单独拎出来减一下就还原了，抑制等于没做。
挑「事件数最小的那个」是因为它信息量最低。

**S6 为什么必须有**：父行 `installs >= 5` **不代表** `artifact × result` 这个交叉子组也达标 ——
`installs=5, results={ failed: 1 }` 会直接披露那一次失败，而它背后可能只有 1 台机器。
交叉子组要发布，得**每一格自己带 distinct installs**，服务端目前给不了。
所以 `lib/normalize.mjs` 连读都不读：读进 viewmodel 就迟早会有人渲染它。

**S7 为什么不是「标注一下」**：分位数是**顺序统计量**，样本少时 `p95` **就等于某一条原始耗时**，
等于把一条原始记录印出来。K=5 保护的是「这一组有几台机器」，它不保护分位数本身。
初稿只给小样本行标了一句「估计不稳」——**标注不减少披露**，所以改成不发布。
⚠️ 20 不是一个被证明过的隐私边界，只是「p95 不再等于最大那一条」的保守起点；
硬保证要服务端在算的时候就取整/分桶。

**文案上「样本太少」与「无法核实门槛」是两句话**，不许合并：把未知说成「太少」
是在断言一件我们并不知道的事，读的人会以为「服务端算过了，就是没人用」。

### 🔴 已知的残余风险：跨表相减

首页并列发布的是**同一批事件的不同切法**（按制品 / 按客户端 / 按 OS…）。
配合一点外部知识，理论上可以拿几张表互相相减，把某一张里被抑制的行推出来。

**这里做到的**（S5）：去掉全部精确的减法锚点。三条一起：
① 每张表不发布总计行；② 被抑制的那一组不报事件合计；
③ 🔴 **只要任何一张表有抑制，顶层 `total` 与 `installs` 就分桶发布**。

③ 是 Codex 第二轮挡下来的：上一版只做了 ①②，页面上却还挂着一个精确的 `total=137`，
而 artifact 表可见行只有 `pr-draft=90` —— 一减就是被抑制组的 47。
**「HTML 里搜不到 47」不等于「47 推不出来」。**
判断在 `lib/publish.mjs` 里做，因为它要把所有表一起看：抑制的强度不是逐表独立的。

**这里做不到的**：一个硬保证。行数、枚举里缺席的取值、跨表的行数差都还是约束条件。
真正闭合要对「整套固定发布的表」做联合抑制 / 可解性校验，只能在服务端做，
列在页面第 99 段与下面的「服务端待补」里。

⚠️ 这一条写在页面上而不是藏在这里 —— 一个看板的读者有权知道它的保证到哪为止。

## 「没有」有很多种，它们必须长得不一样

上线后每个数字都会是 0，而且会持续一段时间。这段时间里页面唯一的职责就是
**说清是链路的哪一环还没通**。

🔴 **把不同的「没有」混成一句话，会让「服务挂了」看起来像「没人用」** ——
那是这个平台能犯的最贵的错：它会让人据此下架一个其实很好用的 skill。

判定顺序是**从外到内**（`lib/state.mjs`）：数据源 → 响应合法性 → 有没有事件 →
维度有没有 → 筛选 → 抑制。倒过来判会把外层故障说成内层空。

| 状态 | 纸样 | 标题 |
|---|---|---|
| 没配端点 | heather + 3px revoked | 汇总端点还没接上。 |
| 连不上 / 超时 / 5xx | 同上 | 汇总端点不可用。 |
| 401/403/404 | 同上 | 汇总端点拒绝了我们。 |
| 200 但形状不对 | 同上 | 端点回了 200，但内容不是我们认得的汇总。 |
| **真实的 0** | 叙述纸（不换纸） | 端点通了，回来的是 0 条事件。 |
| 维度服务端没算 | manilla（旧纸） | 这个维度服务端还没算。 |
| 维度算了但空 | 记录纸 | 这个维度服务端算了，但一行都没有。 |
| 回了行但全被丢掉 | heather（同故障档） | 服务端回了行，但我们一行都不认得。 |
| 筛没了（**目前用不到**） | 记录纸 | 当前筛选条件下没有行。 |
| 全被抑制 | grey（撤走暖色） | 有行，但一行都发布不出来。 |
| 全被抑制（分位数表） | grey | 有行，但一行分位数都发布不出来。 |

🔴 **页面上没有筛选器，所以「候选行为 0」不许说成「筛没了」** —— 那是一句在当前页面里
**不可能为真**的话。它的真实含义是「这个维度本来就是空的」，最常见的原因是这批事件
根本不带这个字段（§2 里 artifact / version / client / scope / ms / reason 都是选填，
`rollback` / `sync-lock` 这类事件本就没有 artifact）。
`viewStateOf()` 有一个 `filtered` 参数，默认 false；将来真加了筛选器再传 true。

🔴 **分位数表全被挡住时用专门那句文案**：通用那句只说得出「装机数不够」，
而真实原因可能是「机器够多、但每台只装过一两次」—— 说错了会把人引去错误的方向。
⚠️ **哪一行卡在哪一道门槛不公开**：逐行成因本身也是信息。

🔴 **「形状不对」这一档要判到里面一层。** `byArtifact: "x"` 这种**容器**形状错误，
初稿会读成一张空表，于是页面说「当前筛选条件下没有行」——**把一次故障说成了一个结论**。
现在容器形状不对一律判 INVALID（`lib/normalize.mjs` 的 `BadShape`）。
`byArtifact: null` / 键缺失仍然是「服务端还没算」，那是合法的。

🔴 **「丢完剩 0 行」不许说成「本来就是空的」。** 取值校验会丢掉脏行（摄入端点无鉴权，
这是对的），但丢完之后剩 0 行是**数据质量问题**，不是一个结论。
`readDimension()` 数了 `dropped`，`viewStateOf()` 据此走 `UNRECOGNIZED_ROWS`。

🔴 **上游不可用时，第 99 段的「缺口清单」不会声称「所有维度都待补」** ——
那张清单是拿实际返回对出来的，没有返回就没有清单（既不是「没有缺口」也不是「全都缺」）。

🔴 **禁止**：「暂无数据」四个字、骨架屏、假数据占位、居中的空盒插画。
骨架屏尤其糟：它说的是「马上就来」，而实际情况是「端点还没部署，这一格半年内都不会有数」。
`test/state.test.mjs` 断言这些文案两两不同，并扫禁用词。

## 访问控制

**方案：中间件里的共享密钥 + HMAC 签名 cookie**（`proxy.js` + `lib/auth.mjs`）。

`DASHBOARD_ACCESS_SECRET` 没配时**整站 503**（fail-closed）。
「忘了配」在部署里最常见，而它的两种后果差别极大：fail-closed 是「没人能看，很快有人报修」，
fail-open 是「所有人都能看，而且没有人会发现」。

### 为什么不用 Vercel 的 Password Protection

两者**强度是同一档**：都是单一共享口令，都没有个人身份、没有按人吊销、
没有「谁在什么时候看了什么」的审计。既然强度一样，取「在我们代码里」的那个 ——
本地与 preview 能一模一样地复现，能写测试（`test/auth.test.mjs`），不依赖套餐档位。

### 它挡得住什么

- 搜索引擎收录（另配 `X-Robots-Tag: noindex, nofollow, noarchive`）
- 被转发出去的链接：拿到 URL 的人打不开
- 没有凭据的爬虫与扫描器
- 未登录时**一次上游请求都不会发出去** —— 门禁在 proxy（旧称 middleware），早于任何数据读取
- CDN / 浏览器缓存泄漏：全站 `Cache-Control: private, no-store`
- 登录 CSRF：`sec-fetch-site` + `Origin` 同源检查
- cookie tossing：`__Host-` 前缀强制 Secure + `Path=/` + 无 `Domain`

### 🔴 它挡不住什么（不粉饰）

- **拿到口令的人。** 口令可转发、可重放，没有个人身份，**没法按人吊销** ——
  有人离职就得换口令、所有人重登。
- **审计。** 我们不知道谁看了什么，也不打算知道（要知道就得记访问者身份）。
- **能读环境变量的人**：Vercel 项目成员、有部署权限的人、CI。
- **Cookie 被偷**：XSS、恶意扩展、被入侵机器上的浏览器 profile。HttpOnly 挡脚本读，挡不住这些。
- **Vercel 平台自身的访问日志。** 它记不记、记多久，不在这份代码里。
  ⚠️ 这与规格 §5.3 对**埋点端点**的「不得记 IP」是两件事（那条约束采集链路），但要知道它存在。
- **暴力猜口令**：只有一道**全局**限速（不按 IP 分桶 —— 我们不读 IP，同 `server/app.mjs` 的纪律）。
  代价是有人狂试会连带挡住别人。真正的防线是口令熵：用 `openssl rand -base64 32`，不要用一个词。
  而且限速桶是**每个实例各一份**的进程内状态，真实速率是「实例数 × 配置值」，best-effort。
- **`X-Robots-Tag` 不是访问控制**，只是别让内容进索引。

> 要审计与按人吊销，正确做法是 SSO（Vercel SSO / OIDC）。**本版没做，这是已知的残余风险，不是遗漏。**

## 部署（Vercel）

**独立的 Vercel 项目**，不能和 `site/` 共用：`site/` 是静态导出（构建时把签名快照渲染成
HTML、运行时不查后端），这里每次访问都要问一次上游、还要跑门禁 proxy。

| 项 | 值 |
|---|---|
| Root Directory | `dashboard` |
| 「包含根目录之外的文件」 | **关掉** —— 本项目不 import 仓库根的任何东西（`lib/whitelist.mjs` 顶部写了为什么抄一份而不是 import） |
| Framework Preset | Next.js |
| Build / Install | `npm run build` / `npm install`（`vercel.json` 里已写死） |
| Node | ≥ 22.13（同仓库） |

环境变量（**Production 与 Preview 都要配，Preview 用不同的口令**）：

| 变量 | 说明 |
|---|---|
| `DASHBOARD_ACCESS_SECRET` | 访问口令。`openssl rand -base64 32`。没配 = 整站 503 |
| `GEOLY_SUMMARY_URL` | 上游 `…/v1/summary` 的完整 URL。**必须 https**（localhost 除外） |
| `GEOLY_TELEMETRY_SUMMARY_TOKEN` | 上游的 Bearer token，与服务端的 `GEOLY_TELEMETRY_SUMMARY_TOKEN` 同值 |

三个都是 **Sensitive / 仅服务端**：Vercel 上不要给它们加 `NEXT_PUBLIC_` 前缀
（加了就会被打进客户端 bundle，而 `test/no-client-secrets.test.mjs` 拦不住一个改了名的变量）。

⚠️ **上线检查单**：
1. `GEOLY_TELEMETRY_SUMMARY_TOKEN` 与服务端那一侧是同一个值 —— 不然页面会一直显示「拒绝了我们」；
2. 服务端确实设了它自己的 `GEOLY_TELEMETRY_SUMMARY_TOKEN`（规格 §5.3：没配就不开这个路由，会回 404）；
3. Preview 部署也有门禁（proxy 对所有环境生效），但**口令要与生产不同**；
4. 仓库根的 `.vercelignore` 里应加上 `dashboard/node_modules`（`site/` 那个项目会上传整个仓库）。

### 🔴 preview 拿的是**另一把** summary token —— 这是有意的

`GEOLY_TELEMETRY_SUMMARY_TOKEN` 在 preview 与 production 两个 target 上是
**不同的值**，而生产端只认 production 那把。所以 **preview 读不到生产聚合**，
它拿到的是 401。

**为什么要这么设**（2026-09-02，Codex 在部署评审里指出）：
Vercel 的 `sensitive` 只是**在 UI 上隐藏取值**，它**挡不住 preview 的代码读取
这个变量**。也就是说，任何能影响一次 preview 构建的人（比如提一张 PR）
都能把生产聚合读出来。而 preview 的用途是看 UI 改动，**它不需要生产数据**。

⚠️ **preview 上看到 401 不是配错了。** dashboard 会显示
「**汇总端点拒绝了我们。** 端点在，但它不认这把 token（401/403），
或者它压根没打开 `/v1/summary`（404）」——那是九种「没有」里的一种，
**它不会被显示成「没人用」**。这正是把「没有」分成九种的意义：
一个读不到数的 preview 必须说自己读不到，而不是给出一个看起来正常的 0。

📌 要让 preview 有数据看，正确做法是**另起一套 telemetry 实例**给 preview 用，
   而不是把生产的 token 发给它。

## 本地跑

```sh
cd dashboard
npm install
DASHBOARD_ACCESS_SECRET=dev-only-secret \
GEOLY_SUMMARY_URL=http://127.0.0.1:8787/v1/summary \
GEOLY_TELEMETRY_SUMMARY_TOKEN=dev-token \
npm run dev
```

上游可以就用仓库里的 `node server/index.mjs`（记得给它设
`GEOLY_TELEMETRY_SUMMARY_TOKEN`，否则 `/v1/summary` 不开、这边会显示「拒绝了我们」——
那正是链路诊断在起作用）。

测试：`npm test`（不需要 `next build`，全部是纯函数与静态扫描）。

🔴 **CI 目前没有接这个项目 —— 这是一个待接线项，不是已经做完的事。**
根仓库的 `.github/workflows/ci.yml` 只装/测根包，所以下面这条「build 后再跑一次」
现在只是一句人工约定。要真正把关，CI 需要加一个 job：
`cd dashboard && npm ci && npm test && npm run build && npm test`
（第二次 `npm test` 才会真的扫到构建产物；把两个密钥变量喂给它，值扫描才生效）。
⚠️ 写这份代码的人无权改 `.github/`，所以这一条留给合并者。

⚠️ **CI 里应该跑两次 `npm test`：`next build` 之前一次、之后一次。**
`test/build-output.test.mjs` 直接扫 `.next/static` 里真的被打进浏览器包的字节
（找 token 变量名、口令、UUID 形状的串）。没有 `.next/static` 时它**跳过**而不是红 ——
让 `npm test` 强制依赖一次完整构建，结果只会是没人跑测试。
它是 `test/no-client-secrets.test.mjs` 那三条**结构性**断言的兜底：
结构断言按源码形态推，推不到动态 `import()`、re-export、路径别名、
`const { X } = process.env` 解构，以及将来可能出现的 Server Action。

## 为什么这里不写第二份聚合

`server/aggregate.mjs` 是聚合逻辑的**唯一**一份。dashboard 只做搬运和过滤
（`lib/normalize.mjs`），不算 P50、不从 `byArtifact` 反推 `byClient`、不补差值。

自己算一份就会分叉，而**分叉不会让任何东西变红** —— 只会让人某天发现两张表对不上、
不知道该信哪一张。缺维度时正确的动作是把缺口列出来（页面第 99 段「服务端待补的聚合」，
那张清单是从实际返回里算出来的，服务端补上一项那里就少一行）。

### 需要服务端新增的聚合（给派活用的清单）

1. 🔴 **顶层 `installs`**：全局去重 `install_id` 数。最要紧的一项 ——
   小样本抑制的判据就是它，没有它所有细分表整表不可见。
2. 🔴 **每个细分行自己的 `installs`**：`{ "<取值>": { "n": …, "installs": … } }`。
   只给顶层一个总数没用，抑制判的是「*这一行*背后有几台机器」。
   ⚠️ 键名**必须叫 `installs`**（一个计数）：任何 `install_id` / `installIds` /
   `byInstallId` 形态的键都会被 dashboard 递归剥掉。
3. **`byReason` / `byClient` / `byVersion` / `byOs` / `byCli` / `byArch` / `byNode` /
   `byKind` / `byScope`** —— §1 的问题 2 全靠它们。
4. **`durations`**：`[{ "version": "…", "n": …, "installs": …, "p50": …, "p95": … }]`。
   分位数在服务端算，不要把原始 `ms` 列表发过来。
   ⚠️ 最好在算的时候就**取整/分桶**（例如按 50ms 向上取整），闭合顺序统计量的披露面。
5. **交叉子组**（`artifact × result` 这类）：每一格自己带 `installs`，否则不要发。
6. **【尚未解决】联合抑制 / 可解性校验**：对「整套固定发布的表」做，闭合跨表相减。
