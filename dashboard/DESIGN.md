## 1. 一句话主张与不可让步的数据约束

**这是一个值班台：先告诉你「这一页现在可不可信」，再给你数字，解释永远排在数字后面。**

它不是一份决策报告，也不是一个「看板」。段号仍然是 `docs/telemetry/00-spec.md` §1 的问题号
（01 哪些 skill 真的在被用 / 02 装失败集中在哪 / 03 一次安装要多久）——
🔴 **改成控制台不等于改成「任意指标墙」**：每一段仍然要能说出自己是拿来做什么决策的（§8.5）。

### 1.1 🔴 八条硬约束（全部是正确性，不是品味）

1. 🔴 **只能展示采集到的东西。** 采集面是穷举白名单：
   `at cli os arch node kind result artifact version client scope ms reason`
   （外加三个采集了但永不上屏的：`schema` / `eid` / `install_id`）。
   **这个清单之外的指标一个都不许画** —— 活跃用户、留存、时长分布、DAU、增长率、
   占比、健康分、**「最后一条事件的时间」/ 数据新鲜度**……**连位置都不要留**。
   不要画一个「以后放留存」的角落。
   ⚠️ **一个必须分清的边界**：顶栏那个「本次读取 …Z」**不是**上面说的「最后更新时间」——
   它是**我们自己发这次请求的时刻**（本机时钟），不来自任何一条事件，也不是从 `at` 算出来的。
   🔴 **从 `at` 派生的任何时间（最后一条事件的时间、首次出现时间、按天分布）都是禁区**，
   那是 T-11 时间线的入口。两者只差一个字，代价差很远，所以文案上必须写成「本次读取」，
   不许简写成「更新于」。
   ⚠️ 唯一一个「不是指标但要显示」的东西是 `hasRolledUp`（历史折算），
   它来自 `rolled_up_before`，**不在事件白名单里**，所以它在版面上必须被标成
   **「来源注记 · 不是指标」**，用与 KPI 不同的卡（§8.4），不许混进 KPI 行。
2. 🔴 **永远不提供「按 install_id 下钻」。** 能把某个 install_id 的事件按时间排开的界面
   **本身就是再识别工具**（源 IP + 稳定 install_id + 时间线 = 机器级追踪，规格 §6 T-11）。
   `install_id` 只用于去重计数。**没有下钻、没有时间线、没有原始 `ms` 列表、
   没有折算水位时间戳、没有 `kinds`/`results` 嵌套分布与交叉子组。**
3. 🔴 **小样本抑制（K=5，判据是去重 install_id 数，不是事件数）必须有明确的视觉表达，
   而且它不能长得像 0。** 见 §10，这是本设计投入最多的一节。
4. 🔴 **有抑制时顶层标量变成分桶区间**（`100–499`）而不是精确值。
   布局必须容得下这种变化：数值槽固定宽度、`tabular-nums`、**不许自适应缩字号**（§8.4）。
5. 🔴 **「没有」有十一种，它们必须长得不一样**（§9）。最要紧的一条：
   **故障绝不能显示成 0** —— 端点没接上 / 不可用 / 拒绝 / 回了不认识的内容，
   一律说「我们没读到数」；只有真收到 0 条才说 0。
6. 🔴 **数字不许被 `text-transform` 或任何格式化改变语义。**
   版本号与制品坐标区分大小写，`1.1.0-rc.1` 被渲染成 `1.1.0-RC.1` 就是把值改了。
   大写只给 `th` 与我们自己造的拉丁标签。
7. 🔴 **全站没有绿色。** 这里没有验证轴：一个 `result: ok` 的埋点计数**不是**一次验证通过，
   给它绿色会让「有人装成功过」看起来像「我们担保过它」。
   `result` 的四个取值（`ok` / `skipped` / `failed` / `corrupt`）一律中性色 + 词。
   （`site/DESIGN.md` 的 `--c-ok` 在这里**根本不存在**，连 token 都不定义 —— 定义了就会有人用。）
8. 🔴 **抑制发生在服务端。** 整个项目没有一个 client component。设计里任何看起来像
   「前端筛选 / 前端展开更多行」的交互都是**错的**：先把未抑制的聚合发给浏览器再隐藏，
   等于把它公开了。本设计里唯一的客户端行为是主题切换与折叠脚注（§13）。

### 1.2 页面上每个数字的来源（实现者必须能逐个追回去）

| 屏上的东西 | 来自 | 白名单字段 |
|---|---|---|
| KPI `events` | `publish().totalOut` | 事件计数（`at` 为每条事件的时点，只用于计数） |
| KPI `distinct installs` | `publish().installsOut` | `install_id` 去重后的**计数**（🔴 ID 本身永不上屏） |
| 细分表的行 `取值` | `data.dimensions[dim].rows[].key` | `artifact` `version` `cli` `client` `os` `arch` `node` `kind` `result` `scope` `reason` |
| 细分表的 `事件数` / `装机数` | 同上的 `events` / `installs` | 计数 |
| 耗时表 `p50` / `p95` | `durations.visible[].p50/p95` | 服务端对 `ms` 的聚合（🔴 不接受原始 `ms` 列表） |
| 「历史折算」 | `hasRolledUp` 布尔 | ⚠️ **不是**采集字段，是**来源注记**（见 §1.1 第 1 条） |
| 数据源状态徽章 | `SOURCE.*` | ⚠️ 不是指标，是链路状态 |
| 顶栏「本次读取 …Z」 | 本机时钟 | ⚠️ **不是**采集字段，也**不是**从 `at` 派生的 —— 是我们发这次请求的时刻 |

🔴 **有抑制时不许渲染 `data.total` / `view.total` 原值**，只能渲染 `totalOut` / `installsOut`。
原值留在 viewmodel 里是给判断用的，不是给渲染用的。

## 2. 视觉性格

### 2.1 为什么不跟 `site/` 的暖米 + 陶土

`site/` 是**对外的 registry 门面**：读者是陌生人，第一件事是建立信任，
所以它用温暖、编辑感、留白充裕的 Anthropic 语言，标题是衬线。

`dashboard` 是**内部值班台**：读者是同一批人，每周看很多次，要的是
「一屏放得下多少事实」和「异常一眼跳出来」。它和 `site/` 的关系是
**「同一家公司的产品页与机房面板」**，不是「同一套皮的两个页面」。
把暖米 + 衬线搬到一个高密度后台上，结果是密度上不去、状态色在暖底上发闷。

所以这里换一套：**冷石墨灰的机箱 + 一个钢蓝的强调色 + 四种去饱和的「墨」**。
冷灰底让四种状态墨（砖红 / 琥珀 / 靛紫 / 冷灰）各自跳得出来，
这正是这个平台最需要的能力 —— 它有十一种「没有」要分。

### 2.2 主动回避的几个「AI 默认样子」

| 套路 | 本设计怎么做 |
|---|---|
| 暖米 + 衬线标题 + 陶土强调 | 那是 `site/` 的语言，这里不用（§2.1） |
| 纯黑底 + 一抹荧光绿 | 暗色是**冷近黑** `#14171B`，不是纯黑；🔴 **全站没有绿色**（§1.1 第 7 条） |
| 紫蓝渐变 hero | **全站零渐变**，唯一的 `repeating-linear-gradient` 是抑制态的斜纹（§10），它是编码不是装饰 |
| Inter / Space Grotesk 安全牌 | **IBM Plex Sans + IBM Plex Mono**（§5） |
| emoji 当章节标记 | 🔴 **界面上零 emoji**（§5.4）。本文档里的 🔴 是给读文档的人的，不上屏 |
| 全部居中 | 全部左对齐。唯一居中的是登录页那张卡本身（卡内左对齐） |
| 到处 `rounded-lg` | 圆角只有 3 / 5 / 8px 三档，表格单元格 0（§6.3）；**没有胶囊** |
| 卡片阴影堆叠 | **全站一处阴影**，只给弹出层（§6.5）。面板靠 1px 发丝线定形 |

## 3. 核心解法：三层版面

这是本次重做要解决的真问题：**解释太多、数字太远**。

### 3.1 三层

页面自上而下永远是同样三层，**顺序即优先级，不许调**：

| 层 | 是什么 | 占多少 | 谁在说话 |
|---|---|---|---|
| **① 状态层** | 顶栏的数据源徽章 + 采集面契约条 | 固定 56 + 34px，常驻 | 「这一页现在可不可信 / 它只能有哪些字段」 |
| **② 数字层** | KPI 卡片、面板、表格、条形 | 版面主体 | 机器在说话 |
| **③ 脚注层** | 面板底部的折叠抽屉、段末的注记、「口径与边界」整页 | 默认收起 | 页面在解释自己 |

🔴 **第一屏（1440×900，未滚动）必须能看见 ①、②，且至少一整行 KPI 与一张面板的表头。**
这是本次重做的验收线，实现完要在真浏览器里量一遍。

### 3.2 🔴 采集面契约条必须常驻，不许折叠

`README.md` 与 `components/privacy.jsx` 有一条硬要求：隐私说明**常驻页面顶部，不折叠、
不做成 tooltip**，因为这个平台是少数几个非工程同事也会看的界面。

**本设计不废除这一条，只把它压扁**：

- 常驻的是一条 34px 高的 **`.collectionbar`**（§8.3）：一行 13 个字段 chip +
  一句话 +「口径与边界 ›」链接。它**不可折叠、不可关闭**，出现在每一页的顶栏正下方。
- 被搬走的是那三段**长论证**（为什么不下钻、K=5 为什么是 5、跨表相减的残余风险），
  它们进导航里独立的一页 **「口径与边界」**（§8.10）。
- 🔴 **独立页只能承接长文，不能取代契约条。** 判据很简单：
  一个只看了首页、一次都没点进「口径与边界」的人，必须仍然知道
  ①这一页只能有那 13 个字段、②`install_id` 不上屏、③有小样本抑制。
  这三件事各占契约条一句。

### 3.3 解释性正文的三个落点（除此之外不许有第四个）

| 落点 | 形态 | 装什么 | 默认 |
|---|---|---|---|
| **deck** | 面板/区段标题下一行，13px，`--c-text-dim`，**最多两行** | 「这一段拿来做什么决策」 | 常显 |
| **抽屉** | `<details class="foot">`，摘要行是「为什么这样算 ›」 | 门槛、成因、口径、残余风险 | **收起** |
| **口径与边界页** | 导航最后一项，整页叙述 | 三段长论证 + 服务端待补清单的说明 | 独立路由 |

🔴 **抽屉里的内容不许是「装饰性长文」**：每一条都要能回答一个具体的「为什么这个格子是这样」。
🔴 **抽屉默认收起，但抑制/故障态的关键句不许放进抽屉** —— 那句必须在告示条正文里（§9）。

## 4. 配色

### 4.1 亮色（`:root`）

```css
/* ── 中性：冷石墨。三层材质：页底 → 面板 → 凹陷 ── */
--c-page:      #E9EBEE;   /* 页面底 */
--c-panel:     #F7F8FA;   /* 面板、卡片、侧栏 */
--c-inset:     #E1E4E9;   /* 凹陷：表头、数值槽、命令块、代码片 */
--c-hairline:  #D2D7DE;   /* 1px 行分隔 */
--c-rule:      #B9C0CA;   /* 面板外框、表格外框、输入框 */
--c-rule-hi:   #98A1AE;   /* 区段界线 */

--c-text:      #14181D;
--c-text-mid:  #3C444E;
--c-text-dim:  #5A626D;

/* ── 强调：钢蓝。🔴 拆成两个 token ── */
--c-accent:     #2F5D8C;  /* 只用于**非文字**：当前项左轨、焦点环、链接下划线、选中边框 */
--c-accent-ink: #245079;  /* 文字安全的钢蓝。链接 hover、小号强调字 */

/* ── 四种「墨」：全是颜料，不是霓虹。🔴 没有绿色，连 token 都不定义 ── */
--c-fault:     #9B2C2C;   /* 砖红：链路故障 —— 我们没读到数 */
--c-withheld:  #7A5410;   /* 琥珀：有数但发布不出来（抑制） */
--c-pending:   #4B4A8F;   /* 靛紫：服务端还没算（这是一条待办，不是故障） */
--c-unknown:   #566070;   /* 冷灰：我们不知道（未提供） */
--c-measure:   #3C444E;   /* 图表条的墨色。🔴 不是 accent —— 见 §11.1 */

/* ── 纸样 paper stocks：状态靠换纸，不靠加饱和度 ── */
--p-fault:     #F6E9E7;
--p-withheld:  #F6EEDD;
--p-pending:   #EBEAF5;
--p-quiet:     #ECEEF1;   /* 中性灰纸：filtered / 停用 / 不适用 */

/* ── 斜纹：抑制态唯一的图案。🔴 它是编码，不是装饰 ── */
--hatch-withheld: repeating-linear-gradient(
    -45deg,
    transparent 0 5px,
    color-mix(in srgb, var(--c-withheld) 16%, transparent) 5px 7px);
```

### 4.2 暗色

同时定义在 `@media (prefers-color-scheme: dark) { :root:not([data-theme="light"]) }`
与 `:root[data-theme="dark"]` 两处（手动切换要能双向覆盖系统偏好）。

```css
--c-page: #14171B; --c-panel: #1C2027; --c-inset: #171A20;
--c-hairline: #2A2F37; --c-rule: #3A414B; --c-rule-hi: #4C545F;
--c-text: #EDEFF2; --c-text-mid: #B6BEC9; --c-text-dim: #97A0AC;
--c-accent: #4E86BE; --c-accent-ink: #86B4E6;
--c-fault: #EF9A94; --c-withheld: #DFB768; --c-pending: #A9A6EE;
--c-unknown: #97A0AC; --c-measure: #8B97A5;
--p-fault: #2C1E1F; --p-withheld: #2A2318; --p-pending: #21203A; --p-quiet: #23262B;
```

- 暗底是**冷近黑** `#14171B`，不是纯黑（纯黑 + 一抹亮色正是要回避的套路）。
- 🔴 暗色的 `--c-accent` 提亮到 `#4E86BE`：亮色那个 `#2F5D8C` 在 `#1C2027` 上画的 1px 线几乎看不见。
- 🔴 `--hatch-withheld` 在暗色里把混色比例提到 **22%**：低透明度斜纹在深底上会糊成一片平色，
  于是「抑制」这个编码整个失效。

### 4.3 使用纪律

- 🔴 **`--c-accent` 不能当正文色**，它只画线不写字；文字一律 `--c-accent-ink`。
- 🔴 **`--c-accent` 不表达任何状态。** 它只说「这里可点 / 这是当前项 / 这里有焦点」。
  一个 `result: ok` 的行**不是钢蓝色的**，一个健康的端点**也不是**。
- 🔴 **四种墨各管一件事，不许串**：

  | 墨 | 只用于 | 绝不用于 |
  |---|---|---|
  | `--c-fault` | 数据源四态 + `unrecognized-rows` | 「没人用」、失败率高的行、`result: failed` 的行 |
  | `--c-withheld` | 小样本抑制（表内 + 顶层分桶） | 「未提供」 |
  | `--c-pending` | 「服务端还没算」与第 99 段的缺口清单 | 故障 |
  | `--c-unknown` | 「未提供」「不适用」「本页当前不可达」 | 抑制 |

  ⚠️ **最容易串的一处**：`result: failed` 是一个**正常的业务计数**（有人装失败了），
  它**不是**故障色。装失败的行用中性墨，和 `ok` 一样。
  砖红只留给「**我们**这一侧读不到数」。
- 🔴 **状态永远同时给词。** 颜色与图标都是第二、第三通道。
- **链接**：`color: inherit` + `text-decoration-color: var(--c-accent)` +
  `text-underline-offset: 3px`；hover 时 `color: var(--c-accent-ink)` 且下划线转 `currentColor`。

### 4.4 实测对比度（预览页内建自测，见 §14.1）

亮色下对 `--c-panel` 的对比度：
`--c-text` 16.7 · `--c-text-mid` 9.2 · `--c-text-dim` 5.8 · `--c-accent-ink` 8.0 ·
`--c-fault` 7.1 · `--c-withheld` 6.4 · `--c-pending` 7.5 · `--c-unknown` 6.6。
每种墨对它自己的纸样都 ≥5.8。`--c-accent` 本身**不写字**，所以不参与文字对比度。

## 5. 字体

### 5.1 两个角色（🔴 没有第三个）

| 角色 | 字体 | 用途 |
|---|---|---|
| Sans | **IBM Plex Sans** | 标题、正文、UI 字符串、字段名、按钮、导航 |
| Mono | **IBM Plex Mono** | 🔴 **机器原文与一切数字**：制品坐标、版本号、原因码、KPI 数值、表格数值、p50/p95、端点 URL |

**为什么是 Plex**：它是为技术文档与工程界面画的，字形冷、字重跨度够、
`0` 带斜杠、`1`/`l`/`I` 分得开 —— 而这一页上有大量 `1.1.0-rc.1` 这种要逐字核对的串。
同时它避开了 Inter / Space Grotesk 这两张「安全牌」。
🔴 **这里没有衬线字**：衬线是 `site/` 谈论数据时的声音，一个值班台不需要它。

### 5.2 `<link>`（实现方直接抄）

```html
<link rel="preconnect" href="https://fonts.googleapis.com">
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin>
<link href="https://fonts.googleapis.com/css2?family=IBM+Plex+Sans:wght@400;500;600;700&family=IBM+Plex+Mono:wght@400;500;600&display=swap" rel="stylesheet">
```

Next.js 用 `next/font/google` 等价加载（`IBM_Plex_Sans` / `IBM_Plex_Mono`），
把返回的 CSS 变量映射到 `--f-sans` / `--f-mono`。

### 5.3 CJK 回落

```css
--f-sans: "IBM Plex Sans", -apple-system, BlinkMacSystemFont, "Segoe UI",
          "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei",
          "IBM Plex Sans SC", "Noto Sans CJK SC", sans-serif;
--f-mono: "IBM Plex Mono", ui-monospace, SFMono-Regular, Menlo, Consolas,
          "PingFang SC", "Microsoft YaHei", monospace;
```

- 🔴 **不 web 加载任何 CJK 字体**（全量 5–10 MB）。中文走系统栈。
- 🔴 **`--f-mono` 里也要挂中文**，否则 mono 表格里夹的中文（「未发布」「未提供」）
  会回落到默认字体，行高当场跳一格 —— 在密度 32px 的表里这个跳非常明显。
- 中文正文行距 1.75（拉丁 1.55）。

### 5.4 大写与 emoji

- 🔴 **`.label`（大写小标签）永远只放拉丁与数字。** `text-transform: uppercase` 对中文无效，
  `letter-spacing: .07em` 会把中文拉散。标签里只要出现一个汉字就换 `.label-cn`
  （sans 11.5px / 600 / 不大写 / 无字距）。实现方应加检查：
  `.label` 的 `textContent` 不得匹配 `/[一-鿿]/`。
- 🔴 **`th` 才 uppercase；`td` / `.v` / `.kpi .v` 必须显式 `text-transform: none`。**
  写成显式声明，不要依赖「默认就是 none」—— 一旦某个祖先加了 uppercase 就全线失守。
- 🔴 **界面上零 emoji。** ⚠️ **这一条现在是破的，实现时要一起修**：
  `lib/state.mjs` 的 `SOURCE_COPY` / `VIEW_COPY` 正文里带着字面量 `🔴` **和 Markdown 的 `**`**
  （例如 `'🔴 这**不是**「没人用」'`），它们会被原样渲染成一个 emoji 加两对星号。
  正确做法：文案里只留纯文字，强调交给告示条的 `<strong>` 与色带。
  （这属于实现改动，本轮不做，但设计上必须写明：**告示条不为 `**` 做任何解析**。）

## 6. 尺度

### 6.1 字号阶梯（后台密度：比 `site/` 整体小一档）

| token | px | line-height | 字体 | 用途 |
|---|---|---|---|---|
| `--fs-kpi` | 30 | 1.1 | mono 500 | KPI 数值（窄屏 26） |
| `--fs-h1` | 19 | 1.3 | sans 600 | 页名（顶栏左） |
| `--fs-h2` | 16 | 1.3 | sans 600 | 区段标题 |
| `--fs-h3` | 13.5 | 1.3 | sans 600 | 面板标题 |
| `--fs-base` | 13 | 1.55 / 1.75 | sans | 正文、deck、抽屉 |
| `--fs-td` | 12.5 | 1.4 | 混 | 表格单元格（值是 mono） |
| `--fs-sm` | 12 | 1.5 | sans | caption、注记 |
| `--fs-label` | 11 | 1.35 | sans 600 | 大写小标签，`letter-spacing: .07em` |

字距：只有 `.label` 加字距。**mono 与表格数值一律不改字距**（改了 hex 与版本号会对不齐）。
🔴 全站数字加 `font-variant-numeric: tabular-nums`：等宽数字让列对齐，
也让 `100–499` 与 `1204` 在同一个槽里不跳。

### 6.2 间距尺度（4 的倍数）

`--sp-1: 4 / --sp-2: 8 / --sp-3: 12 / --sp-4: 16 / --sp-5: 20 / --sp-6: 28 / --sp-7: 40 / --sp-8: 56`

- 区段之间 `--sp-7`；面板之间 `--sp-4`；面板内边距 `--sp-4`；行内间隙 `--sp-2`。
- 🔴 **表格行高 32px、单元格纵向 padding 7px**，不在尺度上，是刻意的密度值。
  留白花在**面板之间**，不花在**表格里面**：站远看是松的，凑近读是密的。
- 固定高度：`--h-topbar: 56px` / `--h-collectionbar: 34px` / `--w-sidebar: 232px` /
  `--h-row: 32px`。四个都给 token，各自在 tokens 文件里注明出处。

### 6.3 圆角

`--r-xs: 3px`（chip、徽章、字段码）/ `--r-sm: 5px`（按钮、输入框、卡内槽）/
`--r-md: 8px`（面板、KPI 卡、告示条、表格容器）。

- 🔴 表格单元格与表格行 **0px**，由外层容器 `overflow: hidden` 裁圆角。
- 🔴 **全站不出现 `border-radius: 999px` 的胶囊。**

### 6.4 边框

| 用法 | 值 |
|---|---|
| 表格行分隔 | `1px solid var(--c-hairline)` |
| 面板外框、表格容器、输入框 | `1px solid var(--c-rule)` |
| 告示条的状态色带 | `border-left: 3px solid <墨>` —— 见下 |
| 导航当前项 | `box-shadow: inset 3px 0 0 var(--c-accent)` |
| 焦点 | `outline: 2px solid var(--c-accent); outline-offset: 2px` |

🔴 **色带在左边，不在顶边** —— 这一条与 `site/DESIGN.md` 相反，是有意的：
`site/` 的警示条是页面级的横幅（顶边像一条封条）；这里的告示条常常出现在
**一个面板的 body 里**，而面板本身已经有一条顶边（header 的下边线），
再加顶边会读成「面板分了两截」。左轨在密集列表里也更容易被余光扫到。

### 6.5 阴影

**全站仅一处**，给弹出层（主题菜单、tooltip）：

```css
--shadow-pop: 0 1px 2px rgba(10,14,20,.06), 0 8px 20px rgba(10,14,20,.12),
              0 0 0 1px var(--c-hairline);
```

🔴 **面板、KPI 卡、表格一律无阴影。**

## 7. 图标：四个族

🔴 **全部内联 SVG。不许引任何图标库、图标字体、外部 CSS。**
（CSP 只放行少数 CDN，且 stylesheet 一律被拦；见根 `AGENTS.md`。）

规格：`viewBox="0 0 16 16"`，`fill="none"`，`stroke="currentColor"`，
`stroke-width="1.5"`，`stroke-linecap="round"`，`stroke-linejoin="round"`。
渲染尺寸：导航 16、面板头 14、告示条 18、量度形态 12。
预览页用 `<svg><symbol>` 雪碧图 + `<use href="#i-xxx">`，生产可直接内联或做成 React 组件。

### 7.1 族与成员

🔴 **族 = 语义类别，族内形态 = 具体取值。**

| 族 | 前缀 | 成员 | 图形 |
|---|---|---|---|
| **导航** | `n-` | `n-overview` | 四格网格 |
| | | `n-usage` | 三根高度不同的竖条 |
| | | `n-failures` | 一条折线在末端断开并打叉 |
| | | `n-latency` | 秒表（圆 + 顶部按钮 + 一根指针） |
| | | `n-gaps` | 虚线方框 + 加号 |
| | | `n-boundary` | 盾形 |
| **状态** | `s-` | 11 个，一态一形 | 见 §9 的表 |
| **量度形态** | `m-` | `m-bucket` | 两端带竖挡的横线（区间） |
| | | `m-floored` | `<` |
| | | `m-unknown` | 一条虚线横 |
| | | `m-withheld` | 斜纹小方块 |
| **中性** | `u-` | `u-chevron` / `u-copy` / `u-external` / `u-info` / `u-theme` / `u-menu` | 常规 |

🔴 **精确值不带图标。** `m-*` 只在**非精确**的量度上出现（分桶 / 压到 `<5` / 未提供 / 未发布）。
给每个数字都挂一个 `=` 是噪音，而且会让「有图标 = 有异常」这个信号失效。

### 7.2 越界纪律（实现方应加静态检查）

- `n-*` 只允许出现在 `.sidebar .nav`、`.panel .head`（面板属于哪一段）与登录卡的品牌行内。
  🔴 **一个 `n-*` 在这三处之外出现，就是有人在拿导航图标当状态图标用** —— 那正是要挡的。
- `s-*` 只允许出现在 `.nothing`（告示条）与 `.statechip`（顶栏徽章）内。
- `m-*` 只允许出现在 `.kpi .v` 与 `td.n` / `.withheld` 内。
- `u-*` 随处可用，但**不得**用于表达任何状态。
- 🔴 任何图标都 `aria-hidden="true"`，且**必须**与一个可见的词同现。
  判据：每个 `<svg>` 的父元素 `textContent.trim().length > 0`。
  （预览页的图例区豁免，生产页面没有对应结构。）

## 8. 组件规格

### 8.1 页面骨架

```
≥1120px
┌──────────────┬──────────────────────────────────────────────────────┐
│ .sidebar     │ .topbar   56px  sticky                               │

│  full height │ .collectionbar  34px  sticky(top:56)  🔴 不可折叠      │
│              │   13 个字段 chip · 一句话 · 「口径与边界 ›」            │
│  ├ 品牌块     ├──────────────────────────────────────────────────────┤
│  └ .nav      │ main  max-width 1240  padding 20 24                  │
│    00 总览    │   §00 KPI 行（3 张卡：2 指标 + 1 来源注记）             │
│    01 使用    │   §01 面板…                                          │
│    02 失败    │   §02 面板…                                          │
│    03 耗时    │   §03 面板…                                          │

└──────────────┴──────────────────────────────────────────────────────┘
```

🔴 **不设右侧栏。** 一旦有右栏，状态与口径就会被塞进去变成脚注 —— 那正是上一版的病。

### 8.2 顶栏 `.topbar` 与数据源徽章 `.statechip`

- 高 56px，`position: sticky; top: 0`，`--c-panel` 底 + 下边 1px `--c-hairline`。
- 左：页名（`--fs-h1`）。紧随其后是**数据源徽章**。
  右：**本次读取时刻**（mono 12px，🔴 文案写「本次读取」，不许写「更新于」，见 §1.1 第 1 条）
  + 主题三态键。
- 徽章形态：`[s-* 图标] + 词`，`--r-xs`，对应墨色 + 对应纸样，1px 同色边框。

🔴 **徽章的作用域只有 `SOURCE.*`（五态）**，一条都不能多：

| SOURCE | 徽章文字 | 墨 / 纸 |
|---|---|---|
| `ok` | `端点已连通` | `--c-text-mid` / `--p-quiet`（🔴 **不是绿色**，见 §1.1 第 7 条） |
| `unconfigured` | `端点未接上` | fault |
| `unreachable` | `端点不可用` | fault |
| `denied` | `端点拒绝了我们` | fault |
| `invalid` | `响应不是汇总` | fault |

🔴 **`unrecognized-rows` 不许进这个徽章。** 它是**某一个维度**的数据质量故障，
端点本身是通的；把它升级成全局徽章等于对整页说「端点不可用」，那是一句假话。
它只出现在那一张面板里（§9）。

🔴 **徽章不是唯一通道**：SOURCE 非 `ok` 时，主区第一块**必须**是整幅的告示条（§8.9），
徽章只是让人在滚到一半时也知道这一页读不到数。

### 8.3 采集面契约条 `.collectionbar`

高 34px，`sticky; top: var(--h-topbar)`，`--c-inset` 底 + 上下 1px `--c-hairline`。
横向 `overflow-x: auto`（窄屏），内容一行：

```
[u-info] 只能有这 13 个字段 ▸ at cli os arch node kind result artifact version client scope ms reason
        · install_id 只用于去重计数，不上屏 · 去重装机数 <5 的细分不展示 · 口径与边界 ›
```

- 字段是 mono 11px 的 chip（`--c-panel` 底 + 1px `--c-hairline` + `--r-xs`）。
- 🔴 **不可折叠、不可关闭、不做成 tooltip**（§3.2）。
- 🔴 三句话是硬内容：①只有这些字段 ②`install_id` 不上屏 ③有小样本抑制。少一句都不行。
- 「口径与边界 ›」是**链接**，不是按钮，指向 §8.10 那一页。

### 8.4 KPI 卡 `.kpi`

一行 3 张，`grid-template-columns: repeat(3, minmax(0,1fr))`，`--sp-4` 间距。
卡：`--c-panel` + 1px `--c-rule` + `--r-md` + `--sp-4` 内边距。

```
┌──────────────────────────────┐
│ EVENTS                 [m-*] │  ← .label（拉丁大写）+ 右上角量度形态图标
│ 1204                         │  ← .v  mono 30px tabular-nums
│ 精确发布                       │  ← .cap 12px --c-text-dim
└──────────────────────────────┘
```

四种量度形态（🔴 **形态本身是信息，不许省略 caption**）：

| 形态 | `.v` 内容 | 图标 | caption | 颜色 |
|---|---|---|---|---|
| `exact` | `1204` | **无** | `精确发布` | `--c-text` |
| `bucketed` | `100–499` | `m-bucket` | `区间发布 · 因为有表被抑制` | `--c-withheld` |
| `floored` | `<5` | `m-floored` | `压到门槛以下 · 精确值本身就是信息` | `--c-withheld` |
| `unknown` | `未提供` | `m-unknown` | `服务端这一版没返回它` | `--c-unknown` |

🔴 **布局必须容得下形态切换**（这是 README 明写的要求）：

```css
.kpi .v {
  font: 500 var(--fs-kpi)/1.1 var(--f-mono);
  font-variant-numeric: tabular-nums;
  min-width: 9ch;              /* 容得下 10000–49999 与「未提供」 */
  text-transform: none;        /* 🔴 显式，见 §5.4 */
  white-space: nowrap;
}
```

**不许**用 `clamp()` / `fit-text` 之类按内容缩字号：那会让「区间」看起来比「精确值」小一号，
读者会以为它次要。宁可让卡变高。

🔴 **第三张卡不是 KPI**，是**来源注记**：

```
┌──────────────────────────────┐
│▌来源注记 · 不是指标            │  ← .label-cn，左侧 3px --c-unknown 竖轨
│▌有一段只剩计数                 │  ← 字号降到 --fs-h2，不是 30px
│▌早于保留期水位的原始事件已丢弃   │
└──────────────────────────────┘
```

它用 `.kpi.sourcenote` 类：左轨 `--c-unknown`、数值字号降到 16px、无 `m-*` 图标。
🔴 **理由**：`hasRolledUp` 来自 `rolled_up_before`，**不在采集面白名单里**（§1.1 第 1 条）。
把它做成和 events 一样大的 KPI，等于宣称它也是一个采集指标。
🔴 **绝不显示那个水位时间戳** —— 只给布尔。

### 8.5 面板 `.panel`

```
┌───────────────────────────────────────────────┐
│ [icon] 按制品坐标   artifact         3 行可见   │ ← .head 40px, --c-panel
│ 这一段的用途是下架决策……                          │ ← .deck (可选, 只在区段第一个面板)
├───────────────────────────────────────────────┤
│ 表格 / 告示条 / 条形                              │ ← .body（表格时铺 --c-inset）
├───────────────────────────────────────────────┤
│ ▸ 为什么这样算                                   │ ← .foot  <details>  默认收起
└───────────────────────────────────────────────┘
```

- `.head`：左 14px 图标 + `h3`（`--fs-h3`）+ 字段码 chip（mono 11px，`--c-inset` 底）+
  `spacer` + 右侧计数 / 状态词（`--fs-sm`，`--c-text-dim`）。
- 🔴 **右侧那个计数只报「可见行数」**，不报候选行数、不报总计。
- `.body.table`：`padding: 0`，底 `--c-inset`（表头与表体材质一致，靠 1px 线分行）。
- `.foot`：`<details>`，`summary` 是 `为什么这样算` + `u-chevron`，13px。

🔴 **每个区段的第一个面板必须带 deck**，一句话说清这一段拿来做什么决策。
改成控制台之后这一条更容易掉 —— 一个没有问题意识的后台，读的人会开始按
「哪张表好看」而不是「哪个问题该答」去用它。

### 8.6 数据表 `.dtable`

🔴 **表格永远包一层 `overflow-x: auto` 的容器**（`.tablewrap`，1px `--c-rule` + `--r-md` +
`overflow: hidden`），表格 `min-width: 560px`。**绝不让 body 横向滚动。**

| 列 | 对齐 | 字体 |
|---|---|---|
| 取值（`artifact` / `version` / `reason` …） | 左 | **mono**（机器原文） |
| 事件数 | 右 | mono tabular |
| 装机数 | 右 | mono tabular |
| 条形（可选，最后一列） | 左，固定 120px | — |

- `th`：`--c-inset` 底、`--fs-label`、uppercase、`--c-text-dim`、下边 1px `--c-rule`。
  🔴 表头写**字段名的英文**（`artifact` / `events` / `installs`），不写中文 —— 它们是拉丁标签。
  中文的列名放在 `.head` 的 `h3` 里（「按制品坐标」）。
- `td`：行高 32px，`--fs-td`，`text-transform: none`（🔴 显式）。
- 行 hover：只改 `background`，**不位移、不加阴影**。
- 🔴 **没有总计行、没有百分比列、没有「按下载量排序」**。排序固定：事件数降序、同数按键名。
- 🔴 **没有「展开更多」**：抑制在服务端做完了，浏览器里根本没有更多行。

### 8.9 告示条 `.nothing`

十一种「没有」共用的形态，靠 `.n-<state>` 修饰：

```
┌─────────────────────────────────────────────────┐
│▌[s-* 18px]  汇总端点不可用。                       │ ← 左轨 3px + 标题 sans 15px 600
│▌ 端点配了，但这一次没拿到回答……                     │ ← 正文 13px
│▌ 先看端点自身是不是活着……                          │ ← .next 13px，--c-text-dim
│▌ 问的是 https://…/v1/summary · 原因码 timeout      │ ← .where mono 11.5px
└─────────────────────────────────────────────────┘
```

- 左轨 3px 对应墨色；底是对应纸样；`--r-md`；内边距 `--sp-4`，左侧 `--sp-4 + 3px`。
- 🔴 **标题、正文、`.next` 三段都常显，不许把任何一段塞进抽屉。**
  这三段就是「说清是链路的哪一环还没通」那件事本身。
- `.where` 只在**数据源四态**出现（掩码过的端点 URL + 短原因码），🔴 **不许带 token、
  不许带异常消息**（栈与消息里可能有内网主机名）。
  🔴 **`.where` 里也不许有计数。** `unrecognized-rows` 那一格最容易犯：
  写一句「丢弃 41 行 · 保留 0 行」看着像在帮忙排查，实际上是在一个**故障**告示条里
  印了一个 `0`，而 §9.3 明令故障态正文内不出现 `0`。`dropped` 是归一化的内部诊断，
  不是可展示的量 —— 它决定**说哪一句话**，不上屏。
- 🔴 **禁止**：「暂无数据」四个字、骨架屏、shimmer、假数据占位、居中的空盒插画、大号加号按钮。
- 尺寸随位置变：整幅（主区第一块）用 `--sp-5` 内边距 + 18px 图标；
  面板内用 `--sp-4` + 16px 图标。**形态不变，只变尺寸。**

导航最后一项，独立路由。整页只有叙述，没有数字。四节：

## 9. 🔴 十一种「没有」的落点

### 9.1 先把数数清楚

`lib/state.mjs` 里：`SOURCE` 5 个（含 `ok`）+ `VIEW` 8 个（含 `ROWS`）。
去掉两个「有数据」的，**「没有」一共 11 种**。

⚠️ 常说的「九种」是这样数出来的：11 − `filtered-empty`（页面上没有筛选器，当前不可达）
− 把两种 `suppressed` 合并成一种。**本设计不合并、也不省略**，给 11 个各自独立的落点 ——
少给一个，将来加筛选器或改门槛时就会有人把两种情况塞进同一句话里。

### 9.2 落点表（三通道叠加：图标 + 左轨墨 + 纸样）

| # | state | 族 | 左轨 | 图标 | 纸样 | 标题（来自 `state.mjs`，不许改） |
|---|---|---|---|---|---|---|
| 1 | `unconfigured` | 故障 | 3px fault | `s-unconfigured` | `--p-fault` | 汇总端点还没接上。 |
| 2 | `unreachable` | 故障 | 3px fault | `s-unreachable` | `--p-fault` | 汇总端点不可用。 |
| 3 | `denied` | 故障 | 3px fault | `s-denied` | `--p-fault` | 汇总端点拒绝了我们。 |
| 4 | `invalid` | 故障 | 3px fault | `s-invalid` | `--p-fault` | 端点回了 200，但内容不是我们认得的汇总。 |

🔴 第 9 行（`filtered-empty`）在**当前页面上不可能为真** —— 页面没有筛选器。
它的落点必须存在（将来加筛选器时要用），但预览页里要标注「当前不可达」，
**生产页面在加筛选器之前不许渲染它**（`viewStateOf()` 的 `filtered` 参数默认 `false`）。

### 9.3 🔴 为什么五个故障态同族同色

**因为最贵的那个错发生在族之间，不在族之内。**
把「服务挂了」看成「没人用」会让人据此下架一个其实很好用的 skill；
而把「端点超时」看成「端点 401」只会让人多花两分钟排查。

所以**族的分离要在余光里成立**（同色同轨同纸），**族内的分离靠图标 + 标题 + `.next`**。
五个故障态的图标两两不同、标题两两不同、下一步动作也两两不同。

🔴 **两条随之而来的硬规则**：

- **`no-events`（真实的 0）与 `no-rows`（维度是空的）绝不换纸、绝不给左轨。**
  全谱十一格里只有这两个是**结论**（「我们问到了，答案就是没有」），
  它们必须看起来**平静**。给一个结论加色带，就是把结论说成一次异常。
  两者之间靠图标（空容器 vs 空表格）与标题分开。
- **故障态里绝不出现阿拉伯数字的 `0`。** 五个故障告示条内不许有任何计数、任何图表、
  任何 `—` 占位。整个主区在 SOURCE 非 `ok` 时**只有告示条**，KPI 卡与面板一并不渲染
  （不是渲染成 0，是**不渲染**）。
  ⚠️ **连正文里引用「零」这个概念时也写汉字「零」，不写 `0`**
  （「这一格绝不当成零」「这一页说的每一句『零』都只是『我们还没问过』」）。
  理由不是洁癖：一个扫一眼的读者只看得见**数字的形状**，
  一个红底格子里的 `0`，无论那句话在说什么，都会被当成这一格的值。
  判据可静态查：`.n-fault` 的 `textContent` 不得匹配
  `/(^|[^0-9A-Za-z._-])0([^0-9A-Za-z._-]|$)/`。
  （`200` / `401` / `404` 这类 HTTP 状态码不受影响 —— 它们是紧邻数字的，判据不会命中。）

### 9.4 判定顺序（视觉不许把它倒过来）

判定顺序是**从外到内**：数据源 → 响应合法性 → 有没有事件 → 维度有没有 → 筛选 → 抑制。
🔴 **版面顺序必须与它一致**：数据源的告示条在最外层（主区第一块），
维度级的在各自面板内，行级的在表格内。
倒过来放会让人先看到「这张表被抑制了」，再往上滚才发现「其实端点根本没连上」。

### 9.5 第 99 段（服务端缺口）的两种形态

- 上游 OK 时：`--p-pending` 的清单面板（`s-not-computed` 图标），一行一项缺的聚合。
- 🔴 上游不可用时：**不许**端出「所有维度都待补」。改用故障族的告示条，
  标题「算不出这张清单。」，正文说清**既不是「没有缺口」也不是「全都缺」**。

## 10. 🔴 抑制态：怎么表达、怎么保证不像 0

这是本设计投入最多的一节，因为它是最容易做错、且做错代价最大的一处。

### 10.1 三个词，两两不许混

| 词 | 含义 | 墨 | 纹理 | 图标 |
|---|---|---|---|---|
| **`0`** | 我们问到了，答案就是零 | `--c-text` | 无 | 无 |
| **`未提供`** | 服务端没给这个数 / 我们没读到 —— **我们不知道** | `--c-unknown` | 无，但**虚线下划** | `m-unknown` |
| **`未发布`** | 候选值存在，但发布不出来 —— **我们知道，但不能给** | `--c-withheld` | **斜纹底** | `m-withheld` / `s-withheld` |

🔴 **把「未提供」写成 0** 是把「不知道」说成「知道且是 0」。
🔴 **把「未发布」写成 0** 是把「有」说成「没有」。
两条都在 `lib/suppress.mjs` / `lib/publish.mjs` 里已经兑现，设计这一侧不许把它们在视觉上合并回去。

### 10.2 🔴 抑制格里的绝对禁令

在任何被抑制的位置（表格单元格、KPI、图表），**下面六种东西一个都不许出现**：

1. `0`（以及**任何**阿拉伯数字，见第 5 条）
2. `—` / `–` / `-`（破折号会被读成 null，而 null 在表格里就是 0 的近义词）
   ⚠️ 这一条只管**值位**（表格里那一格）。抑制态告示条的**正文**里用「——」当标点是正常的，
   静态检查要把两类分开，否则会报出一堆假的不达标。
3. `N/A` / `n/a`
4. 空白单元格
5. 任何**其他**数字（包括被抑制的行数 —— 它不属于这一格，见 §10.4）
6. 长度为 0 的条形（画一根 0 长的条 = 画了一个 0）

⚠️ **这条现在是破的**：`components/dimension-table.jsx` 与 `components/durations.jsx`
在抑制行里输出的是 `—`。实现时必须改成「斜纹 + `未发布` + `m-withheld`」。

**必须出现的**是这三件事同时在场：**琥珀墨 + 斜纹底 + 汉字词「未发布」**。
三通道里任意两个失效（灰度打印、色觉差异、图标没加载）时，剩下那一个仍然说得清。

🔴 **「整表被抑制」的告示条也要带那三个字。**
最容易漏的就是这一处：告示条已经有琥珀 + 斜纹 + 一句「有行，但一行都发布不出来」，
看起来够了 —— 但**斜纹是 `background-image`，读屏读不到**，而那句标题里没有「未发布」，
于是对读屏用户这一格只剩一句可以被读成「没有数据」的话。
做法：`.hd` 里在图标与标题之间插一个 `<span class="withheld">未发布</span>`。
判据：**每一个 `.withheld-row > td` 与每一个 `.n-withheld` 的 `textContent` 都必须包含「未发布」。**

### 10.3 抑制行 `.withheld-row` 的形态

🔴 **抑制行不是数据行，所以它不按列对齐** —— 它是一整行 `colspan` 到底的横条：

```html
<tr class="withheld-row">
  <td colspan="4">
    <span class="withheld">
      <svg class="i" aria-hidden="true"><use href="#i-s-withheld"/></svg>
      未发布
    </span>
    <span class="wr-note">这些行存在，但发布不出来</span>
  </td>
</tr>
```

```css
.withheld-row > td {
  background: var(--p-withheld);
  background-image: var(--hatch-withheld);
  border-top: 1px solid var(--c-withheld);
  color: var(--c-withheld);
}
.withheld { display:inline-flex; gap:6px; align-items:center; font-weight:600; }
```

**为什么 colspan 而不是逐列填**：逐列填就得在「事件数」「装机数」两个数值格里各放一个东西，
而那两个格子的读者预期是**数字**；无论放什么，眼睛都会把它当成一个量。
横条把它从「数据网格」里整个抬出来，读者一眼看到的是「这里有一段被拿掉了」。

🔴 **横条上不写行数、不写事件合计**（后者是最便宜的减法锚点，S5）。

### 10.4 行数与成因放在哪

S2 允许报告「被抑制的行数」，S5 禁止报告它们的事件合计。**行数放在表格外的 caption**：

```
3 行未发布 · 2 行去重装机数不足 5 · 1 行被互补抑制连带拿掉
```

- 位置：`.tablewrap` 下方的 `.cap`（12px，`--c-text-dim`），🔴 **不在任何斜纹格里**。
- 🔴 **「样本太少」与「无法核实门槛」必须是两句话，不许合并**：
  把未知说成「太少」是在断言一件我们并不知道的事，读的人会以为「服务端算过了，就是没人用」。
  三种成因各自的措辞：
  - `small` → `N 行的去重装机数不足 5`
  - `unverifiable` → `N 行服务端没给去重装机数，无法核实门槛（按不达标处理）`
  - `complementary` → `N 行被互补抑制连带拿掉 —— 只抑制一行时，减一下就还原了`
- 🔴 **不许逐行说明哪一行卡在哪一道门槛**：逐行成因本身也是信息。
- 三种成因的**长解释**进 `.foot` 抽屉。

### 10.5 顶层标量分桶时的表达

见 §8.4 的 `bucketed` 形态。三条补充：

- 🔴 KPI 的 caption 必须写出**因果**：`区间发布 · 因为有表被抑制`。
  只写「区间」不写原因，读者会以为服务端就只给了一个区间。
- 🔴 区间用 **en dash `–`**，不是连字符，也不是 `~`。并且 `.v` 里**不许有空格**
  （`100–499`，不是 `100 – 499`）—— 有空格时 `tabular-nums` 的槽宽会跳。
- 分桶发生时，**三张卡里只有真正被分桶的那张变琥珀**。
  `installs` 是 `未提供` 时它是冷灰的 `m-unknown`，不是琥珀 —— 两回事（§10.1）。

### 10.6 耗时表的两种「缺」

| 情况 | 显示 | 为什么 |
|---|---|---|
| 整表被挡住 | `suppressed-quantile` 告示条（§9 第 11 行） | 通用那句只说得出「装机数不够」，而真实原因可能是「机器够多、但每台只装过一两次」 |
| 某几行被挡住 | 一条 `.withheld-row` 横条 | 同 §10.3 |
| `p50` / `p95` 服务端没给 | 🔴 **`未提供` + `m-unknown`（冷灰）** | 这是 unknown 不是 withheld，**绝不能画成斜纹**，也不能画成 `—` |

## 11. 图表：只有两种

### 11.1 横向条形 `.bar`（细分表最后一列）

```html
<td class="barcell">
  <span class="bar" style="--w: 62%"><i></i></span>
</td>
```

```css
.bar { display:block; height:6px; border-radius:2px; background: var(--c-inset); }
.bar > i { display:block; height:100%; width:var(--w); border-radius:2px;
           background: var(--c-measure); }
```

🔴 **四条硬规则**：

1. **条长按「本表可见行的最大事件数」归一，不按总数。**
   按总数归一等于把总数画在版面上，而总数在有抑制时是分桶发布的（S5）——
   画一根按精确总数算出来的条，等于把刚分桶掉的那个精确值又漏了回去。
2. **必须在表下写明这一点**，一字不差的意思：
   > 条长表示事件数，按本表可见行的最大值归一；它不表示占比，也不表示总量。

   ⚠️ 不写这句就会被读成占比 —— 尤其是互补抑制之后常常只剩一两行可见，
   那时最长的条就是 100% 宽，看起来像「这一个取值占了全部」。
3. **条的颜色是 `--c-measure`（中性墨），不是 `--c-accent`。**
   强调色只表达「可点 / 当前项 / 焦点」（§4.3）；把数据条画成强调色，
   等于让读者以为条形是可以点的，也污染了强调色的语义。
4. **不给抑制行画条**（哪怕是 0 长的）。抑制行是 colspan 横条，根本没有这一列。

### 11.2 p50→p95 区间条（耗时表最后一列）

一条水平轨 + 两个端点：`p50` 是实心小方，`p95` 是空心小方，中间连线 `--c-measure`。
刻度按**本表可见行的最大 p95** 归一，同样要写明。

🔴 **端点旁不重复写数字**（数字已经在前两列），条只负责「哪一版明显更慢」这个形状判断。
🔴 `p50` 或 `p95` 为 `未提供` 时**不画这条轨**，画一个冷灰的 `m-unknown` + `未提供`。

### 11.3 🔴 没有第三种，以及为什么

| 想画的 | 为什么不画 |
|---|---|
| **饼图 / 100% 堆叠条 / 任何百分比** | 它们隐含「各部分之和 = 全部」。发布一个占比，等于发布了总计行 —— 违反 S5「表内没有总计行」。而且抑制之后各部分根本加不到 100%，画出来就是错的 |
| **时间序列折线（按天的事件数）** | ① 服务端 `/v1/summary` 根本不返回按时间的聚合，dashboard **不许自己算第二份**；② 时间线正是 T-11 的另一半。🔴 **连位置都不留**，不要画一个「以后放趋势」的空槽 |
| **热力图 / 交叉表（`artifact × result`）** | 交叉子组要发布，得每一格自己带 distinct installs，服务端给不了。`lib/normalize.mjs` **连读都不读** |
| **仪表盘指针 / 健康分 / 达标率** | 需要一个「应该是多少」的基准，我们没有这种东西。造一个就是撒谎 |
| **地图** | 没有地理位置字段。采集面里从来没有过 |
| **稀疏线 sparkline** | 同时间序列 |

### 12.1 🔴 宽内容处理（实测踩过的坑）

grid / flex 子项默认 `min-width: auto`，一个 `white-space: nowrap` 的长制品坐标
就能把整条轨道撑开，于是 body 横向滚动。每个容器都要显式归零：

```css
.main > *, .kpirow > *, .grid2 > *, .panel, .panel .body,
.tablewrap, .kpi, .nothing > div, .collectionbar > * { min-width: 0; }
```

- 表格包 `overflow-x: auto`，`min-width: 560px`。
- 制品坐标（`skill:ns/name@1.2.0`）在 `td` 里 `overflow-wrap: anywhere`，
  🔴 **但不许 `word-break: break-all`**：那会在版本号中间断行，让人抄错。
- 顶栏元素 `white-space: nowrap`，否则 56px 的 sticky 条会被撑成两行盖住正文。
- 🔴 验收判据：**375px 下 `document.documentElement.scrollWidth === 375`。**

## 13. 动效

**全部动效就下面这几条，多一条都是错。**

| 场景 | 规格 | 为什么 |
|---|---|---|
| hover / press | `background`、`border-color` `100ms linear` | 只改颜色。表格行 hover **不许位移** |
| 折叠抽屉 | `grid-template-rows: 0fr → 1fr`，`140ms ease-out` | `.foot` 的展开 |
| 焦点 | `outline` 无过渡 | 键盘导航必须立刻可见 |
| 加载中 | **静态**占位横线（`--c-inset`），**无 shimmer** | 🔴 骨架屏说的是「马上就来」，而实际情况是「端点还没部署，这一格半年内都不会有数」 |

**禁止**：入场动画、滚动触发动画、数字滚动（count-up）、渐变流动、页面切换过渡、
骨架屏 shimmer、任何 >200ms 的过渡。
🔴 **数字滚动尤其禁止**：它会让一个分桶区间在滚动过程中短暂显示成一串精确数字。

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after { transition: none !important; animation: none !important; }
}
```

## 14. 可访问性

- 状态、量度形态、抑制**永远同时有文字**，颜色与图标都不是唯一通道。
- 图标一律 `aria-hidden="true"`，语义由旁边的词给（§7.2）。
- 🔴 告示条是页面既有的静态事实，不是实时通知：
  用 `<div class="nothing" role="group" aria-labelledby="<标题 id>">`。
  **不要用 `role="alert"` / `role="status"`** —— 那两个是 live region，
  会在页面加载时被朗读成「刚刚发生的事」。
  ⚠️ 现有 `components/nothing.jsx` 用的是 `role="status"`，实现时要改。
- 🔴 **抑制格必须对屏幕阅读器也说「未发布」**：斜纹是 `background-image`，读屏读不到；
  词必须是真实文本。**不许**用 `::before { content: "未发布" }`。
- 表格用 `<th scope="col">`；数值列 `text-align: right`。
- 主题三态按钮（跟随系统 / 亮 / 暗），状态写进 `data-theme`，按钮文字直接给出当前值。
  同时定义 `@media (prefers-color-scheme: dark)` 与 `:root[data-theme="dark"]` 两处。
- 侧栏导航是 `<nav><ul><li><a aria-current="page">`。
- 区段 `scroll-margin-top: calc(var(--h-topbar) + var(--h-collectionbar) + 8px)`。

### 14.1 对比度自测

`design-preview.html` 底部内建「跑一遍对比度自测」按钮（WCAG 2.x 相对亮度）。
两个坑，写自动化检查时别踩：

- **不要把单字符文本排除在外**（用 `length >= 1`）。这一页有大量单字符与短串
  （`<5`、`0` 这类），恰好是最容易配错色的。
- **颜色解析不要用正则**：`color-mix()` 的计算值不是 `rgb(a,b,c)` 形状。
  用 canvas 2D 的 `fillStyle` + `getImageData` 解析（预览页里的 `auditContrast()` 可直接抄）。

⚠️ **斜纹会拉低有效背景亮度**，而 `getComputedStyle().backgroundColor` 读不到 `background-image`。
所以抑制格的墨色是按**纯 `--p-withheld` 底**算出来的 6.4:1 上再留了余量：
斜纹的混色比例定在 16%（暗色 22%）。改斜纹浓度要重测。

🔴 **这个自测覆盖不到的三件事，要人工过一遍**（不要因为它报「全部达标」就以为完了）：

1. **SVG 图形的非文字对比度**（图标线条对底，要求 ≥3:1）—— 它量的是文本节点。
2. **半透明叠加**：行 hover 的 `color-mix(--c-accent 6%)` 会改有效底色，
   而自测只取第一个不透明祖先。hover 态要单独看一眼。
3. **动态状态**：hover / `:focus` / `[open]` 下的配色。静态扫 DOM 扫不到 ——
   `site/DESIGN.md` 的「绿色唯一化」就是在动态状态上破的功，这里同理。

### 14.2 预览页里的另一个按钮：设计不变量检查

`auditInvariants()` 逐条查 §5.4 / §7.2 / §10.2 / §12.1 里能静态查的硬约束：
`.label` 不含中文、`td`/`.kpi .v` 的 `text-transform` 为 `none`、
**抑制位里一个数字都没有且都含「未发布」**、没有 0 长条形、跨族图标越界为 0、
每个图标都 `aria-hidden` 且配了词、界面文本零 emoji、`scrollWidth <= clientWidth`。

🔴 **生产实现应把同样这几条搬进构建期检查** —— 形状族与「抑制不像 0」这两件事靠人自觉是守不住的。

## 16. 实现者最容易做错的地方（照这个自查）

1. **把解释性长正文搬回版面主体。** 三个落点（deck / 抽屉 / 口径页）之外不许有第四个（§3.3）。
2. **顺手把采集面契约条做成可折叠或 tooltip。** 它必须常驻、不可折叠（§3.2）。
   独立的「口径与边界」页**只能承接长文，不能取代它**。
3. **把抑制格画成 `—` 或空白。** 破折号会被读成 null，null 在表格里就是 0 的近义词。
   必须是「琥珀 + 斜纹 + `未发布`」三通道（§10.2）。⚠️ 现有实现正是 `—`。
4. **把「未提供」和「未发布」混成一句话或一个颜色。**
   前者是「我们不知道」（冷灰 + 虚线），后者是「我们知道但不给」（琥珀 + 斜纹）（§10.1）。
5. **在故障告示条附近渲染 0。** SOURCE 非 `ok` 时 KPI 与面板**不渲染**，不是渲染成 0（§9.3）。
6. **把 `unrecognized-rows` 升级成顶栏的全局徽章。** 端点是通的，那是一张表的数据质量问题（§8.2）。
7. **给 `no-events` 加色带或换纸。** 它是唯一一个「真实的 0」，必须看起来平静（§9.3）。
8. **画饼图 / 百分比 / 占比列。** 它们隐含总计 = 100%，等于发布了总计行，违反 S5（§11.3）。
9. **画时间趋势图，或者留一个「以后放趋势」的空槽。** 没有这个聚合，而且时间线是 T-11 的一半（§11.3）。
10. **条形按总数归一。** 有抑制时总数是分桶发布的，按精确总数画条等于把它又漏回去（§11.1）。
11. **把条形画成强调色。** 强调色只表达「可点 / 当前项 / 焦点」（§4.3）。
12. **给 `result: ok` 上绿色，或给它任何颜色。** 全站没有绿色；四个 `result` 取值一律中性（§1.1 第 7 条）。
13. **把 `result: failed` 的行涂成砖红。** 砖红只留给「**我们**读不到数」，不给业务上的失败计数（§4.3）。
14. **把 `hasRolledUp` 做成第三个 KPI。** 它不在采集面白名单里，必须是「来源注记」卡（§8.4）。
15. **显示折算水位的时间戳。** 只给布尔（§1.1 第 2 条）。
16. **让 KPI 数值按内容缩字号。** 分桶区间会显得比精确值次要；固定 `min-width: 9ch`（§8.4）。
17. **`text-transform: uppercase` 泄漏到数据上。** `1.1.0-rc.1` → `1.1.0-RC.1` 是把值改了。
    `td` / `.v` 要**显式**写 `text-transform: none`（§5.4）。
18. **在被抑制的那一组上报事件合计，或者给表加总计行。** 那是最便宜的减法锚点（§10.3、S5）。
19. **逐行公开「这一行卡在哪道门槛」。** 逐行成因本身也是信息（§10.4）。
20. **给告示条用 `role="alert"` / `role="status"`。** 它是既有事实，不是刚发生的事（§14）。
21. **忘了 `min-width: 0`。** 一个长制品坐标就能让 375px 下横向滚动（§12.1）。
22. **把 `state.mjs` 文案里的 emoji 和 `**` 原样渲染。** 界面上零 emoji，告示条不解析 Markdown（§5.4）。
23. **加一个「展开更多行」或前端筛选。** 抑制在服务端做完了，浏览器里没有更多行（§1.1 第 8 条）。
24. **在登录页上放采集面契约条或数据源徽章。** 那时我们还没问过任何东西（§15）。
25. **把 `filtered-empty` 在没有筛选器时渲染出来。** 那是一句在当前页面里不可能为真的话（§9.2）。
26. **把顶栏的「本次读取」写成「更新于」，或者顺手加一个「最后一条事件的时间」。**
    前者是我们自己的时钟，后者是从 `at` 派生的时间线入口（§1.1 第 1 条）。
27. **在故障告示条的 `.where` 里写计数**（「丢弃 41 行 · 保留 0 行」）。
    那是在一个故障格里印了一个 `0`（§8.9、§9.3）。
28. **只给表内抑制行加「未发布」，忘了整表抑制的告示条。**
    斜纹读屏读不到，那一格就只剩一句能被读成「没有数据」的话（§10.2）。
